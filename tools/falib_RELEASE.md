# falib 1.0 — Fighters Anthology LIB 製作工具 Release 說明

2026-11-26　|　適用：FA.EXE 原版、FA_BIG　|　工具：`falib.py`（Python 3.8 以上，不需安裝其他套件）

這份說明寫給**自己製作或修改 .LIB 的人**，不論你用 falib 還是 FA ToolKit。
下面的注意事項是我們在 JKPFA6 製作過程中，經過 33 次遊戲內測試，加上反組譯 FA.EXE 找出來的。
**這些規則違反了，遊戲會「隨機」當掉**，而且一般的解壓工具通常檢查不出來。

---

## 一、一定要知道的 5 條規則

### 1. LIB 的結尾必須留空白（最重要）

FA.EXE 解壓 LIB 裡的檔案時，**每次固定讀 2048 個位元組**，不會檢查這個檔是不是已經結束。
如果 LIB 最後幾個壓縮檔離檔案結尾不到 2 KB，遊戲就會讀到 LIB 檔案外面，然後當掉。

- 會不會出事，取決於最後那幾個檔的大小和位置，所以看起來像**隨機**：同樣的內容，換一種分法、多加或少一個檔，就可能從好變壞、從壞變好。
- 什麼時候當掉，要看是哪個檔出界：物件檔（NT、OT、JT、SEE…）會在**快速任務建立**時當掉，圖片和模型（PIC、SH）通常在**進入任務**時當掉，沒被用到的就不會出事。
- **falib 會自動在每個 LIB 結尾補 4 KB 的 0**，遊戲完全不受影響。
- **用 ToolKit 編的 LIB 沒有這個保護。** 發布前一定要用 `falib.py verify` 檢查（見第三節）。

### 2. 壓縮只能用「原廠 PKWare 會用的寫法」

PKWare 壓縮格式允許「往回 1 個位元組」和「往回 4096 個位元組」的複製，也允許長度 517、518；
但真正的 PKWare 壓縮程式（ToolKit 和原廠都是）從來不用，FA.EXE 的解壓也處理不了。

- 合法範圍：往回距離 **2 到 4095**，長度 **最多 516**。
- 自己寫壓縮程式的人要特別注意：一般的解壓程式都能正確解開這些寫法，所以自己檢查會「通過」，進遊戲才當掉。
- falib 只產生合法的寫法，`verify` 也會擋下不合法的。

### 3. LIB 檔名要符合 DOS 8.3

FA.EXE 每個 LIB 檔名只保留 14 個位元組。請用 `XXXXXXXX.LIB` 這種最多 8 個字元的名字，例如 `JKPFA6_A.LIB`。

### 4. 數量上限

| | 原版 FA.EXE | FA_BIG |
|---|---|---|
| 遊戲目錄裡的 LIB 檔數量（含原廠 4 個） | **20** | 256 |
| 所有 LIB 裡的檔案，加上遊戲目錄的散檔，總數 | **9,950** | 100,000 |

原廠 LIB 就占了 7,505 個檔，所以自製內容加上散檔大約只剩 2,400 個的空間。falib 接近上限時會警告。

### 5. 同名的檔：「檔案日期比較新」的贏

同一個檔名同時出現在好幾個地方（不同 LIB、或 LIB 和遊戲目錄的散檔）時，遊戲只用**所在檔案日期最新**的那一份。
比較的是 LIB 檔本身或散檔的修改時間，精確到分鐘；同一分鐘的話，用哪一份不一定。

- 剛編好的 LIB 會蓋過遊戲目錄裡比較舊的散檔。之後你又改了散檔，就換散檔生效。
- **不要讓同一個檔出現在兩個自製 LIB 裡**，否則用哪一份就看哪個 LIB 比較新。
- 原廠 LIB 是 1998、2015 年的檔案，所以任何自製 LIB 都會蓋過原廠的同名檔。這是正常的覆蓋方式。

## 二、以前流傳、但其實不是原因的說法

我們都實際測過，以下這些**都不會**造成當掉：

- LIB 檔名本身（只要符合 8.3），以及 LIB 之間的先後順序
- 一個 LIB 裡同類型檔案的數量（只要總數在上限內）
- LIB 裡檔案的排列順序
- 檔案不壓縮、直接存放（原廠音樂就是這樣存的）
- falib 放在每個 LIB 裡的 `$FALIB.INF` 校驗清單（遊戲會忽略它，就跟 ToolKit 的 `$TOOLKIT.INF` 一樣）

## 三、發布前的檢查（請每次都做）

```
python falib.py verify <放 LIB 的資料夾>
```

最後一行必須是 **`RESULT: PASSED`**。檢查的項目有：

1. 檔頭、索引、檔名格式都正確；
2. **沒有任何檔會被遊戲讀出界**（規則 1）；
3. 每個檔都能完整解開，而且只用合法的壓縮寫法（規則 2）；
4. falib 編的 LIB 會比對校驗清單，**哪怕只壞了 1 個位元，也查得出來**，不需要原始檔；
5. 同一個檔沒有重複出現在兩個自製 LIB 裡（規則 5）。

玩家下載之後，也可以用同一個指令檢查，確認檔案在傳輸中沒有損壞。

如果是 ToolKit 編的 LIB 沒通過（通常是規則 1），請改用 falib 重新編譯：先用 `falib.py import` 把 ToolKit 專案裡的修改收回來，再 `build`。

## 四、falib 的功能一覽

| 指令 | 用途 |
|---|---|
| `build` | 依照清單檔（例如 `LIB/JKPFA6.txt`）直接從原始檔編出所有 LIB；自動補結尾、用合法壓縮、編完自動 `verify` |
| `build --toolkit` | 同時產生 FA ToolKit 能開的專案目錄（ITEM.DAT、PROJECT.DAT、README.TXT、FA_0.LIB） |
| `verify` | 檢查任何 LIB（自製、ToolKit 編的、已安裝的） |
| `check --game` | 編之前先看：哪些檔會改變、遊戲目錄的散檔有沒有不一致 |
| `import` | 把 ToolKit 專案裡的修改收回原始檔，三方比對，不猜哪個是新版 |
| `unpack` / `list` | 解開或列出任何 LIB，原廠的也可以 |

速度：第一次完整編譯 JKPFA6（8 個 LIB）約 2 分鐘，之後只重壓有變動的檔，幾秒鐘就好。ToolKit 編一個 JKP54D 要約 10 分鐘。

## 五、安裝 JKPFA6 的方式

1. 遊戲目錄保留原廠 `FA_1.LIB`、`FA_2.LIB`、`FA_4B.LIB`、`FA_4D.LIB` 和 `_HUD.LIB`。
2. 移走所有舊版 JKPFA 的 LIB：`FA_JKPFA54_*.LIB`、`FA_JKPFA_B.LIB`、`_MAP.LIB`、`_MUSIC.LIB`。
3. 放入 8 個 `JKPFA6_*.LIB`：A 飛機、B 地面與船艦、C 武器、D 3D 模型、E 圖片、F 音效、M 地圖、S 音樂。

已測試：原版 FA.EXE 和 FA_BIG，快速任務建立和進入任務都正常（2026-11-26）。
