Making FA LIBs that do not crash

做出不會當掉的 FA LIB

A home-made .LIB can unpack perfectly in every tool and still crash Fighters Anthology, sometimes when the mission builder opens, sometimes when the mission starts, and seemingly at random. We tracked it down with 33 in-game tests and by disassembling FA.EXE. Here are the five rules every LIB must follow, the free tool that follows them for you, and a checker for your own LIBs.

自己做的 .LIB 用任何工具都解得開，進遊戲卻還是可能當掉：有時在打開任務建立時，有時在進入任務時，看起來毫無規律。我們做了 33 次遊戲內測試，又反組譯 FA.EXE，終於找到原因。這一頁整理每個 LIB 都必須遵守的 5 條規則、會自動幫你遵守的免費工具，以及一個能檢查你自己 LIB 的工具。

The five rules

5 條規則

1

Leave empty space at the end of every LIB the random crash

每個 LIB 的結尾都要留空白 隨機當掉的元兇

FA maps the whole LIB into memory and unpacks a file by reading it in 2,048-byte chunks. It never checks where the file ends. If a compressed file sits within about 2 KB of the end of the LIB, the last chunk is read past the end of the LIB and the game crashes.

FA 把整個 LIB 對應到記憶體，解壓檔案時每次讀 2,048 個位元組，從不檢查這個檔在哪裡結束。如果某個壓縮檔離 LIB 結尾不到約 2 KB，最後那一塊就會讀到 LIB 外面，遊戲當場當掉。

It depends only on the size and position of the last few files, so adding, removing or moving one file can make it appear or vanish. Object files (NT, OT, JT, SEE) crash the mission builder; pictures and shapes (PIC, SH) crash the mission start. Files that are never loaded never crash.

會不會出事只看最後幾個檔的大小和位置，所以多一個、少一個或搬一個檔，問題就可能出現或消失。物件檔（NT、OT、JT、SEE）會讓任務建立當掉，圖片和模型（PIC、SH）會讓進入任務時當掉，沒被用到的檔就不會出事。

falib adds 4 KB of zeros after the data. The game never reads them. LIBs built with the FA ToolKit have no such padding: check them before release.

falib 會在資料後面補 4 KB 的 0，遊戲不會讀到它們。FA ToolKit 編的 LIB 沒有這段空白，發布前請先檢查。

2

Compress only the way the real PKWare library does

壓縮只能用原廠 PKWare 會用的方式

The PKWare format can express copies from 1 byte back and from 4,096 bytes back, and lengths of 517 and 518. The real PKWare compressor never writes them, and FA's decoder cannot handle them. Allowed: distance 2 to 4,095, length up to 516.

PKWare 的格式可以寫「往回 1 個位元組」和「往回 4,096 個位元組」的複製，也可以寫長度 517、518。真正的 PKWare 壓縮程式從來不寫這些，FA 的解壓也處理不了。合法範圍：往回 2 到 4,095，長度最多 516。

Normal unpackers accept the illegal forms, so a home-made compressor "passes" every test and crashes only in the game.

一般的解壓程式都能接受這些不合法的寫法，所以自己寫的壓縮器在任何測試裡都會「通過」，只有進遊戲才會當掉。

3

LIB names in DOS 8.3 form

LIB 檔名要符合 DOS 8.3

FA keeps each LIB name in a 14-byte slot. Use at most 8 characters before .LIB, for example JKPFA6_A.LIB.

FA 每個 LIB 檔名只留 14 個位元組。.LIB 前面最多 8 個字元，例如 JKPFA6_A.LIB。

5

Same name twice: the newest file date wins

同名的檔：檔案日期最新的贏

If a name appears in several LIBs or as a loose file, FA keeps only the copy whose LIB file or loose file is newest (to the minute). A freshly built LIB beats older loose files; editing a loose file later makes it win again. Never put the same file into two of your own LIBs.

同一個檔名出現在好幾個 LIB 或散檔時，FA 只用所在檔案（LIB 檔或散檔）日期最新的那一份，比到分鐘。剛編好的 LIB 會蓋過比較舊的散檔；之後又改了散檔，就換散檔生效。不要把同一個檔放進兩個自製 LIB。

Check your LIBs in the browser

在瀏覽器裡檢查你的 LIB

Drop one or more .LIB files (or a whole set). Nothing is uploaded: the check runs on your computer. It tests the LIB index, rule 1 (read past the end), rule 3 (8.3 name) and rule 5 (a name in two of the LIBs you dropped). For the complete check, including rule 2 and the checksum list, use python falib.py verify.

把一個或多個 .LIB（或整套）拖進來。檔案不會上傳，檢查在你的電腦上進行。會檢查 LIB 索引、規則 1（讀出界）、規則 3（8.3 檔名）和規則 5（同一個檔名出現在你拖進來的兩個 LIB 裡）。完整檢查（包括規則 2 和校驗清單）請用 python falib.py verify。

Before every release

每次發布前

python falib.py verify <folder with your LIBs>

The last line must be RESULT: PASSED. It checks the index, rule 1, every file unpacks using only legal PKWare matches (rule 2), the $FALIB.INF checksum list (catches even a single damaged bit, no source files needed), and that no file is in two of your LIBs. Players can run the same command after downloading.

最後一行一定要是 RESULT: PASSED。它會檢查索引、規則 1、每個檔都能解開而且只用合法的 PKWare 寫法（規則 2）、$FALIB.INF 校驗清單（就算只壞 1 個位元也查得出來，不需要原始檔），以及沒有檔案重複出現在兩個自製 LIB 裡。玩家下載後也可以執行同一個指令。

A ToolKit-built LIB that fails rule 1: run falib.py import on its ToolKit project to bring your work back into the source folders, then build the release with falib.py build. falib also writes ToolKit project folders, so people who prefer the ToolKit can keep using it.
ToolKit 編的 LIB 沒通過規則 1：用 falib.py import 把 ToolKit 專案裡的修改收回原始檔，再用 falib.py build 編正式版。falib 也會產生 ToolKit 專案目錄，喜歡用 ToolKit 的人可以照常使用。

Not the cause (all tested)

不是原因的說法（都測過）

  • The LIB name itself (as long as it is 8.3) and the order of LIBs.
  • How many files of one type a LIB holds (within the limits of rule 4).
  • The order of files inside a LIB.
  • Files stored without compression (the factory music is stored that way).
  • The $FALIB.INF checksum entry falib adds (FA ignores it, like the ToolKit's $TOOLKIT.INF).
  • LIB 檔名本身（只要符合 8.3），以及 LIB 之間的先後順序。
  • 一個 LIB 裡同類型檔案的數量（在規則 4 的上限內）。
  • LIB 裡檔案的排列順序。
  • 不壓縮直接存放的檔（原廠音樂就是這樣存的）。
  • falib 加的 $FALIB.INF 校驗項目（FA 會忽略它，就像 ToolKit 的 $TOOLKIT.INF）。

falib at a glance

falib 功能一覽

buildBuilds every LIB straight from the source folders and a file list (no ITEM.DAT editing). Pads, compresses legally, verifies.依清單直接從原始檔編出所有 LIB（不用手改 ITEM.DAT），自動補空白、用合法壓縮、編完就檢查。
build --toolkitAlso writes FA ToolKit project folders (ITEM.DAT, PROJECT.DAT, README.TXT, FA_0.LIB).同時產生 FA ToolKit 專案目錄（ITEM.DAT、PROJECT.DAT、README.TXT、FA_0.LIB）。

unpack · listUnpack or list any LIB, factory ones included.解開或列出任何 LIB，原廠的也行。

Python 3.8+, no extra packages. A full build of all 8 JKPFA6 LIBs takes about 2 minutes the first time and seconds after that (the ToolKit needed about 10 minutes for one LIB). Technical notes: FA_LIB_build.MD.

需要 Python 3.8 以上，不用裝其他套件。第一次完整編譯 JKPFA6 的 8 個 LIB 約 2 分鐘，之後只要幾秒（ToolKit 編一個 LIB 要約 10 分鐘）。技術細節：FA_LIB_build.MD。

Install JKPFA6

安裝 JKPFA6

  1. Keep the factory FA_1.LIB, FA_2.LIB, FA_4B.LIB, FA_4D.LIB and _HUD.LIB.
  2. Remove every older JKPFA LIB: FA_JKPFA54_*.LIB, FA_JKPFA_B.LIB, _MAP.LIB, _MUSIC.LIB.
  3. Copy in the eight JKPFA6_*.LIB: A aircraft, B ground units and ships, C weapons, D 3D shapes, E pictures, F sound effects, M maps, S music.
  1. 保留原廠的 FA_1.LIB、FA_2.LIB、FA_4B.LIB、FA_4D.LIB 和 _HUD.LIB。
  2. 移走所有舊版 JKPFA 的 LIB：FA_JKPFA54_*.LIB、FA_JKPFA_B.LIB、_MAP.LIB、_MUSIC.LIB。
  3. 放入 8 個 JKPFA6_*.LIB：A 飛機、B 地面單位與船艦、C 武器、D 3D 模型、E 圖片、F 音效、M 地圖、S 音樂。
