# FA 的 SH 模型編修筆記

這份筆記說明怎麼修改 Fighters Anthology 的 `.SH` 模型（增加點數和面數、改形狀、加新零件），並讓修改後的檔案在 FA.EXE 裡正常顯示。
內容來自 2026-11 用 F-14、F-15、F/A-18 系列（C/D/E/F/藍天使/EA-18G）實測成功的做法，相關工具在 `tools/shgen/`：
第 1～7 節是基礎；第 8～13 節是 F/A-18 和 EA-18G 學到的（加大 CODE、加外掛和派龍架、遮擋、穿透、改完外形要一起改的東西）。

| 工具 | 用途 |
|---|---|
| `sh_subdivide.py` | 把大的貼圖面 1 分 4，增加點數，貼圖照比例內插（F14X、F15X） |
| `f14_nose.py` | 搬動頂點、拿掉面、加新幾何（機鼻重畫成漸縮環圈、機鼻下 pod，F14N） |
| `sh_renormal.py` | 手動搬過頂點後，重算動到的面的法向量和平面點 |
| `sh_morph.py` | 把一台的頂點修改（例如 F18C→F18E）套到同系列另一台（雙座 F18） |
| `sh_tjfix.py` | 補頂點搬動後的縫隙（T 接點、flaps 和主翼重合點） |
| `f18g_growler.py` | EA-18G：加大 CODE、加油箱/莢艙/派龍架零件、排畫面順序（第 8～11 節的完整範例） |
| `sh_tree.py` | 走訪畫面順序樹，找出把兩個位址分開的節點（第 10 節） |
| `tools/sh_texture.html` | 網頁檢查：貼圖、面色、改過的區塊都看得到 |

## 1. 檔案結構重點

- SH 是 PE（DOSX）檔，模型的位元組碼在 `CODE` 區段。`CODE+6` 是 u16 的縮放：1 個頂點單位 = 2^(shift-8) 呎（F-14 的 shift 是 8，所以 1 單位 = 1 呎）。
- **CODE 結尾附近有簽章 `01 02 03 02 01 02 03 02 01`。** FA.EXE 載入 SH（0x41E990）時，CODE 只複製到簽章為止；簽章後面是匯入跳板 `ff 25 [IAT]`，FA 拿來當變數區。
- 相對位移都是 rel16（±32 KB），x86 片段和變數位址則靠 `.reloc`（type 3，HIGHLOW）重定位。
- 貼圖：`E2 00` 加 14 位元組的 PIC 檔名（例如 `_F14.PIC`）。FA 靠它找紋理檔。可以改成**同樣 14 位元組內**的別的名字（不足補 0，例如 `_f18.PIC`→`_f18g.PIC`），但檔案裡**每一個** `E2 00` 都要改（F18 有 6 個），而且對應的 PIC 檔要存在。

## 2. 位元組碼指令（FA.EXE 0x5183A0 指令表）

分派方式是取 esi 處的 u16，用低位元組查表。

| 指令 | 格式 | 說明 |
|---|---|---|
| `00 00` | | 返回 |
| `1E` | 1 位元組 | 返回（面和面之間常見，**不是填充**） |
| `12 00 rel16` | | 呼叫，目標 = rel16 之後 + rel |
| `38 rel16` | 1 位元組指令 | 跳躍，目標 = rel16 之後 + rel |
| `48 00 rel16` | | 跳躍（2 位元組形式） |
| `82 00 n target` | 後面接 n×(x,y,z) i16 | 把 n 個點載入全域頂點表，從第 target/8 格開始 |
| `F6 idx16 色號 nx ny nz` | 7 位元組 | 設定頂點表第 idx 點的亮度（+7）；法向量 i8，順序是 x、上、前 |
| `FC` | 見下 | 面 |
| `06 00 n1 d1 n2 d2 n3 d3 relA relB` | 18 位元組 | 3D 平面測試：Σn·(眼睛+d) ≥ 0 時先呼叫 A 再呼叫 B，否則先 B 後 A |
| `0C 00` / `0E 00` / `10 00` | 14 位元組 | 2D 平面測試，分別用（上、前）、（x、前）、（x、上） |
| `6C 00 var val relA relB` | | 用變數做比較 |
| `C4 00` | | 放置子零件（位置、旋轉、rel16 指向零件），起落架和可變翼都用它 |
| `F0 00` | | 一段給 FA 直接執行的 x86 程式（零件控制） |

眼睛位置（模型單位，x、上、前）放在 0x51cdaa、0x51cdac、0x51cdae。

### FC 面的格式（處理程式 0x4D43DC）

```
FC  u16 旗標  u16 色號（低位元組 = 色號）
    [旗標 & 0x60] 法向量 3×i16（x、上、前，朝外，長度 32767）
                  ＋平面上一點（旗標 0x200 ? 3×i8 : 3×i16，順序 x、上、前）
    u8 點數
    索引（旗標 0x400 ? u16 : u8）
    [旗標 & 0x04] UV（旗標 0x100 ? 每點 u8 u,v : 每點 u16 u,v）
```

- UV 是 PIC 的像素座標，原點在左上。**PIC 的列是由下往上存的**（檔案第 r 列 = 貼圖 v = h-1-r）。
- 色號 0 的貼圖面：貼圖裡 FF 的像素是透明的（起落架、輪子、座艙蓋）。
- 旗標 0x40：用法向量做背面剔除。0x20：用法向量算光影。0x01：單色。**0x02：Gouraud 底色（用每點亮度）**。
- 面的頂點順序：在 (x,y,z) 下 ΣPk×Pk+1 指向**內側**。存的法向量 = −(Nx, Nz, Ny) 正規化後 ×32767。

## 3. 頂點表上限

全域頂點表在 0x515F90，每點 8 位元組，到 0x517BB0 為止，**最多 900 點**（一個物件全部 LOD 共用）。
F-14 主體用 0～370，零件用到 470。新加的點放在 480 以後最安全。

## 4. 怎麼加東西：掛勾法（不移動任何原有位元組）

原有的相對位移、x86 程式和重定位都不用動，做法如下：

1. **新資料插在簽章之前。** 把簽章和後面的跳板整段往後移 L 位元組；位置或目標落在簽章之後的重定位全部 +L，再重建 `.reloc` 表。
   CODE 的 VirtualSize、SizeOfRawData、SizeOfCode 都要更新，後面區段的 PointerToRawData 也要往後移。
   可用空間 = 下一個區段（.idata）的 VA − CODE 的 VA − CODE 長度（F-14 約 4 KB，F18F 只有 1.7 KB）。不夠時見第 8 節。
   程式在 `sh_subdivide.py` 的 `insert_blocks()`，可以直接 import 來用。
2. **在原本位置掛勾：** 把一個面（或一個節點）的位元組改成 `12 00 rel16`（呼叫新區塊）＋`38 rel16`（跳到原本那段的結尾），其餘填 `1E`。
3. **新區塊的內容：** `82` 載入新點 → **每個新點都要一筆 `F6`** → `FC` 面 → `00 00` 返回。
4. **拿掉一個面：** 改成 `38 rel16`，跳到它的結尾。
5. **一樣長的改寫**（例如三角形換成另一個三角形）可以直接原地覆蓋。

## 5. 注意事項（都是實際踩過的坑）

- **新資料不能放在簽章後面。** 第一版放在檔尾，FA 一切到外部視角就當機，因為那段不會被載入。
- **新點一定要有 F6。** 有 0x02 旗標的面會先畫一層 Gouraud 底色，用的是頂點表每點的亮度（+7），而這個值只有 F6 會設定。
  少了 F6，就會沿用上一個物件留下的值，貼圖白色（FF）透出底色的地方會變成彩色雜訊。新點的法向量可以取相鄰原有點的平均。
- **FA 照順序畫面，沒有 z-buffer。** SH 本身是一棵 BSP，用 06/0C/0E/10 平面測試決定子樹的先後。
  - 加在**原本的面的位置**（同一平面上的細分）時，順序自然正確。
  - 加**新的凸出物**時要自己包一個平面測試。例如 pod 在機鼻底面下方：眼睛在底面以下就先畫機身再畫 pod，否則反過來。
  - 新零件本身要是凸的，每個面都開背面剔除（0x40），就不用再排序。
  - F-14 的主體 BSP 根節點在 CODE+0x1007。F14N 把它換成呼叫一個區塊：先判斷眼睛在 y=95 的前面還是後面，再判斷是否在機鼻底面以下，依此決定機身、機鼻、pod 的先後。
- **頂點座標是整數**（F-14 是 1 呎）。細分時的中點和縮小的環圈都會四捨五入，很小的形狀要注意點重疊。重疊的點要從面裡拿掉，少於 3 點的面就不要輸出。
- **搬動頂點後要重算碰到它的面的法向量和平面點**，否則背面剔除和光影會錯。
- **細分面時新索引會超過 255**，要加上 0x400 旗標（u16 索引）。UV 照原本面的 0x100 決定用 8 位元或 16 位元。
- **不要用 GitHub 網頁上的「下載」存 SH**，那樣存到的是 HTML 頁面（160 KB），不是 SH（30 多 KB）。請從 raw 連結下載，或直接拿工具的輸出。
- 原檔有 1 單位左右的左右不對稱（F-14 右上機鼻比左邊寬 1 呎），修改前先用網頁檢查。

## 6. 檢查流程

1. 用工具產生檔案到 `SHX/`。
2. 在 `tools/sh_texture.html` 選檔案，打開「畫出邊線」，從上、下、左右、前方和斜下方各看一次。
3. 進 FA 測試：外部視角繞一圈、靠近看貼圖面、從下方看。

## 7. 從 3D 模型建立新機身（`tools/shgen/glb2sh/`）

第一版做法（F14G，2026-11）：保留原檔的標頭、零件和中低 LOD，只把高 LOD 主體整段換掉。

- **F-14 的高 LOD 主體是 CODE 0x80～0x3B95**：`82` 主體頂點、`F6`、BSP，裡面夾著零件控制。0x3B95 以後是零件的頂點和面，0x4906 起是中 LOD，0x653B 起是低 LOD。
- **整段換掉後，後面往前移 delta**：標頭裡 4 個相對位移（CODE+0x10 的 `F2`、0x60 和 0x68 的 `C8`、0x6C 的 `A6`）要加 delta；舊區段的重定位全部丟掉，後面的位置都加 delta，再加上新區段自己的重定位。
  **只有指向 CODE 裡的數值才加 delta。** 簽章後面的跳板 `ff 25 [IAT]` 指向 `.idata`，不能動；F14G 第一版把它也移了，FA 連進入飛行都不行。
- **零件控制照原檔的 F0 樣式重新組**：`F0 00` 後面是 x86，用 `cmp word [變數],1; jne` 判斷，用 `call $+5; pop ebx` 找到 `C4` 再改它的角度欄位（C4+8 航向、+0xA 俯仰、+0xC 滾轉），最後用 `push 回到的位址; push do_start_interp; ret` 回到位元組碼。變數是 `.idata` 匯入的 `_PLgearDown`、`_PLgearPos`、`_PLswingWing` 等的跳板位址，都需要重定位。
- **頂點表**：零件的 `82` 載入到固定的格子（F-14 是 371 以後），而零件可能在主體畫到一半時才畫，所以新主體不能超過 371 點。
- **畫面順序編譯器**（`bsp.py`）：面 g 可能被 f 遮住的條件是「f 有點在 g 的平面前面，而且 g 有點在 f 的平面後面」。把這個關係建成圖，沒有環的部分照拓撲順序畫就對了；有環才用 `06` 平面切開。零件當成一個方塊物件一起排序。F14G 只用了 41 個節點、切 10 個面。
- **檢查**：`sh_paint.py` 照 FA 的方式執行位元組碼（不用 z-buffer）畫出來，可以檢查畫面順序；網頁 `sh_texture.html` 用 z-buffer，只能檢查外型。

## 8. CODE 空間不夠：把後面的區段整體往後移 0x1000（`grow_vas`）

F18F 在 CODE 和 `.idata` 之間只剩 1738 位元組，放不下 EA-18G 的外掛。做法是讓 CODE 變長，把後面的區段（`.idata`、`.reloc`、`$$DOSX`）的 **VA** 一起往後移 0x1000 的倍數。Kuoyi 已在遊戲裡確認可以正常載入（2026-11-14）。

- 可行的原因：FA 的 SH 載入程式（0x41E990）是依每個區段自己的 VA 來換算 RVA，ImageBase 是 0（絕對位址 = RVA），所以只要整體一致地移動就安全。
- `f18g_growler.py` 的 `grow_vas(d, delta)` 會做這些事（可以直接 import）：
  1. 重定位指到的 dword，如果值 ≥ 被移動區段的起點，就 +delta（要先用**舊的**配置讀值）。
  2. 匯入描述（import descriptor）裡的 OriginalFirstThunk、Name、FirstThunk，和 thunk 陣列裡的名稱 RVA 都 +delta（序號匯入 0x80000000 不動）。
  3. 用移動後的頁面重建 `.reloc` 表，並更新資料目錄裡的大小。
  4. 16 個資料目錄、區段標頭的 VirtualAddress、SizeOfImage 都 +delta。
- 流程：先照第 4 節把新資料插在簽章之前；如果 CODE 長度超過 `.idata` 的 VA，就 `grow_vas` 一個 0x1000 的倍數，然後**重新產生一次**（簽章後跳板的位址也跟著變了）。
- **簽章後的 `ff 25 [IAT]` 跳板是控制變數的位址**（`_PLgearDown`、`_PLleftFlap`、`_PLbrake`、`_PLhook`、`_PLafterBurner`、`_PLbayOpen` 等）。它們在 CODE 裡，F0 x86 片段用重定位指向它們；IAT 本身在 `.idata`，所以這些值會被正確地加上 delta。不要手動去移它們（F14G 第一版就是這樣讓 FA 進不了飛行）。

## 9. 加外掛和派龍架（新增點和面）

EA-18G 的翼下油箱、ALQ-99 莢艙、翼尖 ALQ-218 和派龍架都是這樣加的：

- **做成共用零件，再用 `C4` 放到多個位置。** 每種外掛只存一份 `82` 頂點＋面（一個零件），7 個位置都用 `C4 00` 加上位置（x、上、前）、旋轉 0、rel16 指向零件。省空間，也不佔用更多頂點格。
- **頂點格：** 零件載入到固定格子（F18 系列用第 480 格以後，`BASE = 480`），而且全部 LOD 加起來不能超過 900 格。外掛零件只在畫的當下用到這些格子，所以不同外掛可以共用同一段格子。
- **面用單色 0x261 旗標**（單色＋背面剔除＋用法向量算光影）。**沒有 0x02**，所以不需要 `F6`，也不會出現 Gouraud 底色雜訊。
- **面方向：** 用 `orient()` 以零件中心判斷，ΣP×P 指向外側時就把頂點順序反過來（FA 的面在 (x,y,z) 下 ΣP×P 指向內側）。法向量 = 外側方向 ×32767，平面點取面上一個頂點。
- **形狀：** 每個零件都要是**凸的**，這樣背面剔除就能讓它自己的面不必排序。圓柱用八角形截面（`lathe()`），機頭要漸縮成尖頭（多加 2～3 圈，半徑 1 → 0.75 → 0.4 → 0），不然看起來很鈍。翼尖 ALQ-218 的尾翼做成方棒上的小片。
- **派龍架**：一塊薄板（x 從 −1 到 0，只有 1 單位厚），從外掛頂部到機翼下表面，只畫 4 個側面。**派龍架獨立成自己的零件**（`pyT`、`pyA`），不要跟外掛放在同一個零件裡，這樣可以單獨控制它的先後（第 10 節）。
- **整數座標：** 頂點都是整數單位（F18 是 2^(shift−8) 呎），最薄只能 1 單位。很小的細節（尾翼、尖頭）四捨五入後容易重疊，重疊點要拿掉。
- **掛載位置（F18G，x、上、前）：** 油箱 (±27, −6, −2)、ALQ-99 (±40, −4, −6)、機腹 ALQ-99 (0, −12, −2)、翼尖 ALQ-218 (±69, 1, −17)。F18 的機翼是**單層面**：x=27 處上方 ≈ 3，x=40 ≈ 2，翼尖 ≈ 1；機腹在上方 ≈ −7/−8。

## 10. 互相遮擋（FA 沒有 z-buffer，全靠畫的先後）

FA 用「畫家演算法」：後畫的蓋掉先畫的。所以要遮住別的東西，就必須**比它晚畫**。

**基本事實（從 FA.EXE 確認）：**
- `06` 節點（0x4d2450）算 Σ nₖ·(眼睛ₖ + dₖ)，**≥ 0 時先畫 A 再畫 B**，否則先 B 後 A。兩邊都畫完後繼續執行下一個指令，所以節點後面要接 `00 00`。
- 眼睛 = 攝影機在模型座標裡的位置。**座標順序不同：** `82` 頂點是 (x, 前, 上)；眼睛、`C4` 位置、`06` 的 n 和 d、`FC` 法向量是 (x, 上, 前)。這是最常搞錯的地方。
- `C4`（0x4d3194）會先把零件位置從眼睛扣掉再畫，所以零件裡的節點用的是零件自己的座標。
- 節點**只能決定兩邊的先後，不能跳過其中一邊**，也不能組合 AND/OR 條件。需要「只在某些角度蓋過去」時，就把同一個東西**畫兩次**（後畫的那次會贏）。

**做法：**
1. **掛在根節點：** 把主 LOD 根節點（`F6` 記錄之後的第一個 `06`）改成 `12 呼叫 → 新區塊` + `38 跳到原節點結尾`，其餘補 `1E`。新區塊裡是一串節點，最後一層是原本根節點的複本（`c[ROOT:ROOT+14]` 加上重新算過的兩個 rel）。
2. **一組外掛一個平面：** 每個節點寫成 (其餘, 這組)：眼睛在這組外掛那一側時，這組就在其他東西全部畫完後才畫。EA-18G 的串法：右翼下 → 右翼尖 → 左翼下 → 左翼尖 → 右派龍 → 左派龍 → 機身。
   - 翼下平面：n = (∓3604, −16384, 819)，d = (±18, −2, 0)，即「眼睛在機翼下方偏外側」。加了 x 的成分，從低處側後方看時近側外掛才會蓋過遠側主輪。
   - 翼尖平面：n = (±10923, 13107, 0)，d = (±20, 0, 0)。
   - 同一側裡油箱和莢艙用 x = ±33 的平面再排一次。
3. **派龍架單獨一個純高度的平面**（n = (0, −16384, 0)，d = (0, −2, 0)，眼睛在機翼高度以下才晚畫）。如果跟外掛共用斜的翼下平面，從機翼上方淺角度看時，派龍架的側面會穿過機翼露出來。
4. **要插在原有節點的兩半之間：** 複製那個節點的平面做一個新節點 B' = (同平面，A = 新物件，B = 原本的 B)，再把原節點的 relB 改指向 B'。EA-18G 的機腹莢艙就是這樣插在左右主輪之間（節點 0xe2a 的兩半），所以遠側輪子被莢艙蓋住，近側輪子又蓋過莢艙。
5. **掛在一個面上：** 把一個面改成 `12 → 區塊` + `38 → 原面結尾` + `1E` 補滿；區塊 = 原面的位元組 + 新的 `C4` + `00 00`。用在「要接在某段原有的畫面順序裡」的地方（EA-18G 在 0x3068 的面掛了機腹派龍架＋莢艙，接在右主輪的 F0 鏈之前）。
6. **先找出結構再動手：** 起落架、襟翼等零件藏在 `F0` x86 區塊後面（F0 執行完會跳到第一個 `push` 的回到位址 − 0x1000）。用 `sh_tree.py 檔案 位址1 位址2` 找出把它們分開的節點。F18G 的兩個主輪都在根節點的 A 邊（右輪 F0 在 0x30d8，左輪 0x34ee），分開它們的是 0xe2a，所以把莢艙插在根節點兩半之間只對一邊有效。
7. **不要加「從下方看就再畫一次」這種補丁**：攝影機在地面附近時眼睛常常就在機腹以下，那一次會把近側輪子蓋掉（EA-18G v8 的錯誤）。

## 11. 穿透（從另一面看得到不該看到的東西）

- **外掛不能碰到機翼。** 機翼只有一層面，外掛頂部只要高過機翼，從上方看就會穿出來。外掛頂部要比機翼低至少 1～2 單位，中間用派龍架接起來。
- **派龍架要細**（1 單位厚），頂端剛好到機翼下表面，不要高過去。
- 平面測試的分界要用**真正的分隔面**（例如機翼高度），不然在分界附近的角度一定會有一邊畫錯。
- 一個零件內如果有兩個會互相穿過的凸塊（外掛＋派龍架放在同一個零件時），零件裡也要放一個 `06` 節點（例如外掛頂部的高度平面）決定兩者先後。

## 12. 改完外形後要一起改的東西（檢查清單）

- **翼尖白線（高 G 凝結尾跡）：** 起點存在標頭 CE 區塊。CODE+0x12 是 `CE 00`，p = CODE+0x14：p+0 是可變翼轉軸（3 個 int32），p+0xC 是可變翼係數（word），**p+0x0E 和 p+0x1A 是左右翼尖兩點**，每點 3 個 int32 (x, 上, 前) ×256（頂點單位）。FA 透過 0x49FD70（0x4A0110 呼叫）讀取。
  **改了機翼外形（加長、改翼尖）一定要把這兩點改到主 LOD 機翼最外側的後緣翼尖頂點**，正負號照原檔的寫法。原廠 F18 是 (−54,1,−17)/(55,0,−16)，E/F 加大翼後改成 (−67,1,−25)/(67,1,−24)。注意頂點緩衝是 (x,前,上)，這裡是 (x,上,前)。
- **法向量：** 搬過頂點就跑 `sh_renormal.py 原檔 改過 輸出`。注意 F18C 在 CODE+8 有一個假的 `82`，所以只從第一個 `E2` 貼圖名稱之後開始掃描。
- **縫隙：** 搬動頂點會破壞 T 接點，襟翼零件的頂點（用主機身座標）也會和主翼對不上。用 `sh_tjfix.py`，之後再跑一次 `sh_renormal`。**貼花的角點（只被一個面用到的頂點）不要動**，動了貼花會變形。
- **中、低 LOD 也要改。** 只改高 LOD 的話，遠處看會變回原本的形狀（E 系列一開始低 LOD 仍是原廠短翼 ±54）。可以用高、中 LOD 的位移場做反距離加權內插套到低 LOD。
- **零件位置：** 機鼻拉長後鼻輪的 `C4` 前後位置要跟著改；起落架艙門、襟翼等零件的頂點如果跟主體重合，也要一起搬。
- **同系列的另一台：** 單座改好後用 `sh_morph.py` 套到雙座（依座標一一對應，找不到的點用內插），比重做一次可靠。

## 13. 上色和貼圖的坑

- **只改面色不夠。** 有 0x02 旗標的面會先畫 Gouraud 底色，顏色來自每個頂點的 `F6` 記錄，貼圖是 255（透明）的地方會露出來。換塗裝時要一起改 `F6` 的色號（F18U 第一版就因為這樣在遊戲裡出現灰藍色）。網頁預覽**沒有模擬**這層底色。
- 要讓一個沒有貼圖的 Gouraud 面變成純色：把 0x02 拿掉（0x263→0x261），再設面色。
- 找 PIC 的空白區時，要掃描**所有**有 UV 的 `FC` 面，包括零件裡的面（起落架支柱用 0x74c 旗標），否則會蓋掉別人的貼圖。
- 色號 0 的貼圖面上，貼圖 255 是透明的；同一塊貼圖被不同面共用時，改一個會影響全部。
- 機翼上的美軍星徽是 FA 自己的國籍標誌貼圖，不在 PIC 裡。
- **`_PLbayOpen` 要保持 0**：F18 系列的垂直尾翼（零件 14/15）掛在這個變數下，設成 1 尾翼會消失。

## 14. 工具和檢查流程（補充）

- `tools/sh_texture.html`（和 `tools/f18_showcase.html`）用 z-buffer 畫，**只能檢查外型，不能檢查遮擋**；它們會畫出掛勾區塊裡的 `C4` 零件和巢狀節點。遮擋只能進 FA 測，或用 `sh_paint.py`（它對 0C/6C 的解讀是猜的，F18 上會有假的細縫）。
- 反組譯 FA.EXE：`pip install capstone`，.text VA 0x1000 對應檔案 0x400，.data VA 0xEB000 對應 0xE9600。指令表在 0x5183A0 + 2×指令碼。
- 進遊戲要測的角度：外部視角繞一圈、從機翼上方淺角度（看穿透）、從下方和側後下方（看外掛和輪子的先後）、地面滑行時的低角度。
- **改裝置上的檔案前先備份**（`FA18E\backup\` 加版本號），寫入前確認檔案時間，不要蓋掉 Kuoyi 自己手改的版本。
- 不要用 GitHub 網頁的「下載」按鈕存 SH（會存到 HTML），用 raw 連結或展示頁的 zip 下載。

## 15. 網頁 SH 編輯器（`tools/sh_editor.html` + `tools/sh_editor_core.js`）
* fash（fashv3.py）讀不到新加的頂點組，原因：它假設每個 82 頂點組都接在前一組後面（slot = 前面點數總和），而且面只用自己那組的點。我們加的組放在 slot 480/500，面又會同時用到新點和機身的點（F-14N 機鼻接縫），所以那些面全部 parse failed。CODE 長大 0x1000 不是原因；fash 的 build 是照檔案位移寫回，仍可用。
* 編輯器的解析：依檔案順序走（82 更新 slot 表、FC 用當下的 slot 表解析索引、F6 記下），遇到 `12 00 rel` + `38` 掛勾就在掛勾當下的 slot 表跟進附加區塊；附加區塊裡的 C4 零件（EA-18G 外掛）每次放置各算一份。原本的零件（起落架、襟翼、可變翼）用 x86 模擬器（evalCtl）放到正確位置。
* 存檔只在原位置改位元組：頂點座標、改到的面的 FC 法向量和平面點、移動點的 F6 法向量、面的色號、翻面（倒過來的索引和 UV）、刪面（改成 `38 rel` 跳過，其餘填 1E）。repo 的 726 個 SH 不改東西存回來和原檔逐位元組相同。
* 加點、加面要長 CODE（掛勾 + grow_vas），編輯器還不做。
